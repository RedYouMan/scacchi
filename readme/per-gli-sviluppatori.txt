Il progetto Scacchi-it è un progetto italiano,  per piattaforma Windows, nato per realizzare un gioco adatto e fruibile dai non vedenti italiani, che devono principalmente ascoltare per giocare.
Tuttavia si è introdotta anche una grafica riproducente la scacchiera, in modo che i familiari possono aiutare e giocare col non vedente.
Sul sito RedYouMan è presentato il gruppo NV&V e le loro finalità. 
Per le funzionalità leggere readme.md
Il progetto ora è totalmente open source.
Per come contribuire leggere contributing.md

In Scacchi-it la grafica fa uso della libreria sfml-2.6.1 ed eventuali cambi di tale libreria necessiterebbero di porting della
parte sfml, questo perchè le versioni superiori sono state ridisegnate diversamente e diverse funzioni sono state modificate/eliminate oppure è cambiato lo standard di nomenclatura passato a quello Camel.

Ambiente di sviluppo
L'ambiente di sviluppo è basato su librerie Windows di Visual Studio 2022 col suo sdk e compilazione basata su cmake (CMAKELISTS.txt) e C17.
Inoltre nell'ambiente è installato python 3.13.

E' consigliata la installazione di Visual Studio 2022 con il suo sdk.
Tuttavia, dopo aver installato le librerie che si porta dietro Visual Studio Community 2022, per maggiore libertà qui abbiamo usato Visual studio code con cmake.
Il risultato è identico, anche se si appoggia alle librerie della installazione di VisualStudio 2022.
Il cmakelist.txt  è presente in ogni directory dei sorgenti cpp insieme alla directory build contenente debug dove viene creato l'eseguibile.
Il make alla fine (post build) copia eseguibile e dll necessarie nella destination_dir configurata nel cmake.
Nel cmakelists.txt risiede il path al sfml-2.6.1 da esplicitare per il proprio ambiente windows.
e la bin dove mettere scacchi.exe
Il cmake fa riferimento ad una directory in cui è installato localmente SFML 2.6.1

I sorgenti in serverScacchi e src-starter sono sorgenti python, producendo alla fine degli exe col comando pyinstaller: 
pyinstaller --onefile <script>.py

I passi di compilazione sono:
1 - cd src/build
2 - cmake ..
3 - cmake --build . > log.txt
 4 - da scacchi si esegue scacchi-start.exe

La directory src-starter  è utilizzata per file python che vengono resi eseguibili. Tali eseguibili sono scacchi-start e clock-start, posti poi nella home directory a mano.

Il progetto è costituito da tre parti:
- motore grafico di navigazione della scacchiera
- motore di controllo

Il motore di navigazione consente di navigare la scacchiera graficamente, utilizzando il mouse, le frecce e il return. Inoltre informa sul nome della casella, se contiene pezzi o se vuota. Infine gestisce tutti i controls da tastiera per il gioco

Consente anche un addestramento alle aperture di gioco (Openings Trainer).
Il motore di gioco, sfrutta il progetto open source stockfish.

Scacchi-it è è commentato nelle parti importanti

Il programma è tipicamente Object Oriented. La scacchiera è una matrice di caselle, che possono contenere o meno i pezzi. Per scelta la cancellazione di un pezzo da una casella è solo logica con un metodo che setta a falso la casella (non occupata) per due motivi:
a) velocità con meno istruzioni
b) ci sono casi in cui si prova a controllare se la mossa è valida ed eventualmente si annulla

Il posizionamento dei pezzi iniziale non prevede, per scelta, che vengano assegnati i nomi alle caselle (a1, b1, etc.) dove sono vuote per due motivi:
a) velocità
b) quando si effettua la mossa si battezza la casella coerentemente col punto di vista da cui giocare

Il punto di vista da cui giocare determina come le caselle sono distribuite nella matrice: la matrice ha sempre le coordinate 0,0 in alto a sinistra, mentre le caselle sono poste in modo da rispettare il punto di vista.
Il bianco sta in riga 7 e i pedoni in 6, il nero in riga 0 e 1
La classe ChessUtility fornisce i metodi opportuni e viene utilizzata ovunque.

Per garantire di ruotare la scacchiera in qualsiasi momento, si utilizza la sospensione e il ricaricamento della posizione in modo che tutto sia di nuovo identico come posizione, mossa etc.

e' stato definito la ROT notation (ROTN) (dal nome e cognome dell'autore) che rispetto alla posizione fen utilizzata negli scacchi è più utile per i non vedenti, anche rispettoaduna immagine di un libro. 
La ROTN è usata per:
- inizializzare la scacchiera (init)
- sospenzione (sospendi) e ripresa (loadFile) della partita
- per la rotazione della scacchiera (sospendi e loadFile)
- per il caricamento dei problemi (loadFile) 
- per registrare la presenza di enpassant nelle sospensioni

La ROTN è una estensione della notazione algebrica delle posizioni e mosse degli scacchi, utilizzata per rendere un applicativo di scacchi di tipo open data. Difatti con essa è possibile interagire con Scacchi-it.

La gestione del caricamento dei file scritti in formato ROTN avviene tramite il sorgente gesfile.cpp
La specifica ufficiale è 2026-07-02-specifica-rotn.md
Le informazioni sulla scrittura della ROTN e il suo utilizzo sono nel Manuale scacchigr.txt

Il metodo checkSquareUnderAttack è un mattoncino base per fare i seguenti controlli:
a) case minacciate dell'arrocco (vedi anche checkCastleUnderAttack)
b) verifica di scacco al re o scacco matto o stallo (vedi cheScacco e cheStallo)
c) se un pezzo è difeso
d) lo scacco matto si basa su checkFreeSquare che usa sempre il mattoncino di sopra
Il concetto dietro a pezzo difeso sibasa sul fatto che è difeso se la casa su cui si trova è minacciata da un pezzo amico.
In cheScacco() si dichiara scacco al re se non è scacco matto.
In particolare per dichiarare scacco matto non ci devono essere case libere di fuga (checkFreeSquare)e il pezzo che da scacco non può essere catturato e non esistono propri pezzi che possono parare lo scacco, ovvero per parare si intende trovare un pezzo che possa mettersi davanti al re.
Un pezzo avversario si può catturare col re se è adistanza 1 e non è difeso, altrimenti occorre verificare se catturabile con altro pezzo.
Tutto questo viene esaminato nella funzione cheScacco() in questions.cpp. Questions.cpp considerache tipi di scacco sono in gioco, se un pezzo è catturabile e se si può interporre.
 
Gli arrocchi sono settati validi alla disposizione iniziale dei pezzi, Poi se si muove la torre, viene posto afalso la validità dell'arrocco relativo (setValid000 o setValid00) attraverso la chiamata del setBusySquare a false sulla casella. 
Altro momento di invalidazione di arrocco ,nel checkMove del re, se il re viene mosso dalla posizione iniziale si invalidano entrambi gli arrocchi.

Per i caricamenti delle posizioni a partire da un file ROTN scritto a mano potrebbe essere necessario per gli arrocchi ambigui tipo che un re o una torre mosso dalla casa iniziale sono poi ritornati al posto iniziale, in tal caso si marca la lista dei pezzi bianchi o neri , separati da ';',con NS (No Short Castle) e/o con NL (No Long Castle) (vedi gesfile.cpp).

Se si riceve una FEN viene sempre aggiunto NS E/o NL, tramite fenpos.cpp, in base allo stato del campo 3 della FEN.

Quando si cambia il punto di vista, lo stato degli arrocchi deve essere trasferito all'altro lato (vedi nav.cpp quando si fa cntrlG)

Le funzionalità cheScacco e cheStallo sono in Questions.cpp

Per evitare troppa manutenzione a checkSquareUnderAttack è stata introdotta anche isPieceDefended che evita la logica negativa e utilizzato solo in casi particolari.

Le classi sono definite in chess.h e la implementazione di esse è in chess.cpp.

Il caricamento dei pezzi con init, il caricamento dei file della ROTN sono in gesfile.cpp

Init() si occupa solo della predisposizione iniziale dei pezzi, mentre loadFile permette con gli opportuni flag 1 o 2 di caricare le sospensioni o i problemi.

Distribuzione dell'applicativo 
Occorre aggiungere le dll dell'estensione dovuta al sdk installato insieme a Visual Studio Community 2022.
In particolare vcruntime140.dll, vcruntime140_1.dll, ucrtbase.dll, msvcp140.dll e le versioni con d.
Nel seguito descriviamo il metodo per individuare le dll e rendere il progrmma autosufficiente, senza necessità di pre-installareun pacchetto redistribuibile.

Per giocare a tali applicazioni si può scegliere tra varie soluzioni:
1 - installare, metodo più semplice, Visual Studio Community 2022 con SDK scelto nel piano di lavoro dell'installer,in modo da avere tutte le dll necessarie
2 - installare il pacchetto ridistribuibile di Visual Studio C++, ultima versione
(vedi: https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170#latest-supported-redistributable-version)
3 - mettere le dll necessarieper rendere autosufficiente l'applicazione

Il metodo 3 è vantaggioso per un utente non vedente.

l'iter per il metodo 3 è il seguente:
1. fare il test senza dll e farsi dire quelle che mancano
2. spacchettare lo zip di lucasg dove è l'exe dell'applicazione(duplicare l'applicazione in un'altra directory)
 (spacchettare Dependencies_x64_Release_.without.peview.exe)
Spacchettando tale pacchetto ci saranno molte dll e file dovuti a lucasg 
3. farsi fare il report da lucesg col comando:
 dependencies.exe -modules -chain -depth 2 scacchi.exe > report.txt
4. per le dll mancanti dal report si vede la directory dove sta ognuna
5. copi da tali directory le dll accanto all'exe dell'applicazione
6. fare la copia dell'applicazione su chiavetta comprensiva di dll senza dependencies e le sue innumerevoli dll e file
7 prima prova su chiavetta prima sandbox)
8 provi su altro pc vergine di Visual Studio(seconda sandbox)
Se supera i punti 7 e 8, successo e fine della "Ricerca della dll perduta".

Architettura per online
Scacchi-it haè il client in c++ di uno dei giocatori e comunica col server in python via socket.
Il server è multiplayer e per garantire questo in modo semplice, dato che il server non usa db, si fa generare al server, grazie al pacchetto secrets, un nome univoco sicuro di room asegnandolo al bianco.

I moduli myNet.cpp e serverScacchi.py gestiscono la comunicazione
Board.cpp e nav.cpp permettono l'utilizzo di Scacchi-it su online con Ctrl-I

Per problemi che nascono dal fatto che si deve far giocare Scacchi-it del bianco o del nero solo su un colore, questo rende problematico alcune funzionalità specie quelle di registrazione, ma anche perchè la lentezza di scrittura può dar fastidio alle socket perdendo il momento in cui viene letta la mossa.
Per questo motivo non è consentita la registrazione  della partita.
Problematico sarebbe anche il calcolo del numero di mossa.

Dall'online sono , quindi, esclusi:
- registrazione della partita
- sospensione e ripristino della partita

Difatti in nav.cpp non viene consentito.

Non viene consentito l'utilizzo di stockfish in modalità online e nemmeno l'opening trainer.
Nè dell'Openings Trainer.

Comandi git
di Mario Turco
La guida la puoi seguire sia da cmd che da visual studio code aprendo la console (ctrl + J)
1) Step 1 segnare i file modificati come pronti per essere inviati, si può fare in vari modi:
 - git add .  ovvero aggiungi tutti i file modificati della cartella corrente
 - git add nomefile aggiungi solo nomefile
 - git add ./cartella aggiungi i file in cartella

2) Step 2, aggiungere un messaggio di commit  git commit -m 'Ho modificato il file xyz'
3) Step 3, pushare verso github, git push


Se vuoi lavorare su un branch per provare un feature nuova e poi poter tornare eventualmente indietro ad una versione precedente:
1) git checkout -b nome_feature dove -b significa 'crea il branch se non esiste', se ti vuoi spostare ad un branch esistente invece basta git checkout nomebranch, ad esempio git checkout main (che è il branch principale del progetto)
2) fai sempre il giro di sopra, git add, git commit, git push

Una volta che ha finito di lavorare su un branch lo puoi mergiare sul main:
1) ti sposti sul main, git checkout main
2) git merge nomebranch, questo unirà nomebranch sul master
3) opzionalmente, puoi anche cancellare nomebranch visto che non ti serve più: git branch -d nomebranch

Per riprendere un sorgente precedente occorre fare
git checkout <codice hash della commit>
poi si fa il branch
